# Internal DecisionSnapshot v2 and history contract

Wave 7 introduces no public API. Internal callers may use `application/evaluateUboDecisionV3Review.js` only with a sealed OwnershipCase revision, schema-1.3 policy data, `runtimeMode: LAB`, an explicit evaluation time, target-bearing case context and checkpoint reference.

The result contains the exact nine immutable phase artifacts and one `ubo-decision-snapshot-v2`. Historical Wave 7 snapshots retain `ubo-requirement-resolution-v1-compat` and `ubo-resolution-plan-v1-compat`. Historical Wave 8 snapshots retain `ubo-requirement-resolution-v2`, the causal InformationNeed set and the private v1 planner bridge. New Wave 9 snapshots pin RequirementResolution v2 and exact `ubo-resolution-plan-v2` output. The plan is created before snapshot construction; the separately returned plan is the same immutable artifact stored in Phase 8 and `pinnedResolutionPlan`.

The v2 verifier dispatches Phase 7 and Phase 8 validation by their pinned algorithms. Wave 7 content remains `TRANSITIONAL_REVIEW_ONLY`; Wave 8 remains `TRANSITIONAL_PLANNER_ONLY`; Wave 9 is `SUCCESSOR_PLANNER_COMPLETE_REVIEW_ONLY`. It cross-checks causal artifacts against Phase 7, verifies need/set/adapter or plan hashes, and rejects diagnostics that reference an unknown causal need. A Wave 9 snapshot additionally verifies the complete plan, current wave, strategy assignments, profile pin and exact Phase 8 plan identity without calling the planner again.

When a RegistryCapabilityProfile is used, the snapshot records its ID, version, canonical hash, entitlement context, freshness/readiness state, governance state and only the used capability-entry IDs. When no profile is supplied, the v2 plan and snapshot explicitly record `NOT_PROVIDED`; no capability coverage is invented. Profile-driven snapshots retain A-15, `LAB`, `REVIEW_ONLY` and `productionAuthorized=false`.

`domain/decisionHistoryV2.js` is the internal version dispatcher. It delegates v1 snapshots to the untouched v1 verifier/reconstructor and v2 snapshots to v2 verification/reconstruction. Reconstruction returns recorded content and never calls current reasoning algorithms, provider capabilities or evidence collection. Cross-version succession requires a linear predecessor and an explicit neutral reason: `POLICY_CHANGED`, `ALGORITHM_CHANGED`, `NEW_FACTS`, `REVIEW_DECISION` or `CUSTOMER_INPUT`.

The internal `projection/ownershipGraphProjectionV2.js` remains a Wave 8 characterization consumer and is not upgraded in Wave 9. The current public `createUboDecisionApplication`, `planUboResolution`, graph/journey projections and Lab accept only their existing versions. They do not select or consume Snapshot v2, RegistryCapabilityProfile v1 or ResolutionPlan v2.
